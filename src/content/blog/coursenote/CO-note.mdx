<InfoBox style="info">
### MIPS ISA Design Principles

1. **Simplicity Favors Regularity**
    - e.g. Length of all instructions are 32 bits.  All arithmetic operations use the same format.
2. **Smaller is Faster**
    - e.g. MIPS has only 32 registers.
3. **Make the Common Case Fast**
    - e.g. The most common instructions can be executed in one cycle.
    - e.g. No load instruction for immediate values.
4. **Good Design Demands Good Compromises**
    - e.g. I-type 只有 16 bits 的 immediate field，要拼出 32 bits 的位址需要 `lui` + `ori`。
    - e.g. Branch, Jump 需要的定址策略不同（Branch 通常都是處理「附近的條件判斷」，Jump 則是處理「跳轉到遠處的函式」），不能盲目統一。
</InfoBox>

Procedure call 就是高階語言的函式呼叫。函式呼叫者叫做 caller，被呼叫者叫做 callee。

{/* 一個 procedure call 流程如下：
1. **caller 將 callee 需要的 parameters 放進 registers**
    - 塞進 `$a0-$a3`
    - 多的 parameters 塞進 stack。

2. **`jal` callee 位址**
    - `$ra = PC + 4`
    - `PC = callee 位址`

3. **Function Prologue**
    - 開 stack frame（讓 `$sp` 往下長）
    - 備份 callee-saved registers，也就是 `$s0-$s7`、caller 的 `$ra`。

4. **Function Body**

5. **Function Epilogue**
    - 將 return value 存到 register
    - 還原 callee-saved registers */}

Leaf Procedure：不會呼叫別的 procedure，已經是整個函式樹的最末端。

Caller 與 Callee 的角色是相對的。


### General-purpose Registers

<InfoBox style="danger">
Caller-saved：如果你是 caller，當你呼叫別人（執行 `jal`）時，你不能預期這些 registers 的值還是一樣的。如果你要用到的話，請在 `jal` 前手動存入 stack。
</InfoBox>

<InfoBox style="success">
Callee-saved：如果你是 callee，當你被呼叫後想用這些 registers，你必須負責在 prologue 將這些 registers 原值存入 stack，並在 epilogue 復原給原本的 caller 使用。
</InfoBox>

<Table>
| 暫存器編號 | 名稱 | 用途 | Preserved on call |
|:--------:|:--------:|:--------:|:--------:|
| 0 | `$zero` | Hardwired to 0 | - |
| 1 | `$at` | 給 assembler 用的 temporary | <Mark color="red">No (Caller-saved)</Mark> |
| 2-3 | `$v0-$v1` | 函式的 return values | <Mark color="red">No (Caller-saved)</Mark> |
| 4-7 | `$a0-$a3` | 函式的 arguments | <Mark color="red">No (Caller-saved)</Mark> |
| 8-15 | `$t0-$t7` | Temporaries，存用完就丟的計算結果 | <Mark color="red">No (Caller-saved)</Mark> |
| 16-23 | `$s0-$s7` | Saved registers，函式呼叫時會被修改 | <Mark color="green">Yes (Callee-saved)</Mark> |
| 24-25 | `$t8-$t9` | 額外的 Temporaries | <Mark color="red">No (Caller-saved)</Mark> |
| 26-27 | `$k0-$k1` | 給 kernel 用的，處理中斷或例外時使用 | - |
| 28 | `$gp` | Global Pointer | <Mark color="green">Yes (Callee-saved)</Mark> |

| 30 | `$fp` | Frame Pointer | <Mark color="green">Yes (Callee-saved)</Mark> |
| 31 | `$ra` | Return Address | <Mark color="green">Yes (Callee-saved)</Mark> |
</Table>

## Arithmetic Operations

### Signed Integers

<Table align="center">
| Positive | Binary | | Negative | Binary |
|:--------:|:--------:|:--------:|:--------:|:--------:|
| 7 | `0111` | $\Leftrightarrow$ | -8 | `1000` |
| 6 | `0110` | $\Leftrightarrow$ | -7 | `1001` |
| 5 | `0101` | $\Leftrightarrow$ | -6 | `1010` |
| 4 | `0100` | $\Leftrightarrow$ | -5 | `1011` |
| 3 | `0011` | $\Leftrightarrow$ | -4 | `1100` |
| 2 | `0010` | $\Leftrightarrow$ | -3 | `1101` |
| 1 | `0001` | $\Leftrightarrow$ | -2 | `1110` |
| 0 | `0000` | $\Leftrightarrow$ | -1 | `1111` |
</Table>

<InfoBox>
Q：$-6$ 的 binary representation 是多少？

A：$-6$ 的對面是 $+5$，因此直接把 $+5$ 的 binary representation `0101` 反轉就好，得到 `1010`。
</InfoBox>

<InfoBox>
Q：`1101` 是誰？

A：`1101` 反轉後是 `0010` 也就是 $+2$，所以找 $+2$ 的對面也就是 $-3$。
</InfoBox>


對於 signed integers，如果要對齊指令格式都要做 sign extension:
- `0110 (+6)` $\rightarrow$ `0000000000000110`（對齊 I-type immediate）
- `1010 (-6)` $\rightarrow$ `1111111111111010`（對齊 I-type immediate）

### Misc.

1. 如果要將一個完整的 32-bit 數值（例如 `0x12345678`）存入 `$t0`，需要做兩個指令：
    ```asm
    lui $t0, 0x1234       # `$t0` 現在是 0x12340000
    ori $t0, $t0, 0x5678  # `$t0` 變成了 0x12345678
    ```
    常用於全域變數定址，因為記憶體位址都是 32-bit。
2. Unsigned 不會觸發 overflow exception；Signed 會觸發 overflow exception。



































## MIPS 定址方式

所謂的「定址方式 (Addressing Modes)」是指：
- 指令如何尋找運算元 (Operands)。
- 如何決定下一個指令跳轉位址。

<div>
  <InfoBox>
    ### PC-relative Addressing
  </InfoBox>

  這是 `beq`、`bne` 指令使用的定址方式。

  $$
  \text{目標位址} = \text{當前 PC} + \text{offset} \times 4
  $$
  offset 範圍 $-2^{15}$ 到 $2^{15} - 1$。

  注意公式沒有 $+4$，因為 `beq`、`bne` 被解碼完之後 PC 就已經被加 $4$ 了。

  Branch 指令有時候會看到 `beq $s1, $s2, LOOP` 之類的寫法，這是給人看的，代表跳轉到標籤 `LOOP`，組譯器翻譯時會計算跳轉的 offset。

  ```asm
    beq $t0, $t1, label   # jump to label
  ```

  此外如果 Branch 要跳很遠，assembler 會搭配 `j` 指令重寫：
  ```asm
    bne $t0, $t1, skip
    j label
  skip:
    
    ...
  label:
  ```


</div>
<div>
  <InfoBox>
    ### Pseudodirect Addressing
  </InfoBox>

  這是 `j`、`jal` 指令使用的定址方式，此類定址方式借用 PC 4 位高位拼出完整的絕對位址。

  <Image img={JType} darkImg={JTypeDark} width="90" />

  1. 32-bit MIPS 的位址也是 32 bits，因此只有 $2^{32}$ 個位址能用，因此只能定址到 4GB 的記憶體。以傳統 MIPS Linux 為例，一個 process 的 kernel space 佔用 2GB，user space 就只剩 2GB 能用。
  2. 32-bit MIPS 所有指令都是 4 bytes，因此指令定址一定都是 4 的倍數，雖然看起來只有 26 bits 能用但實際上可以定址到 $2^{28} = 256$ MB 的記憶體。
  3. 既然定址只能到 28 bits，剩下的 4 bits 就會直接借當前 PC 的高位，這代表 `j`、`jal` 指令雖然比 `beq`、`bne` 能跳更遠，但只能在 256 MB 空間內跳轉。
</div>
</Columns>








































## Atomic Read/Write: `ll` and `sc`

這兩個指令是為了防止讀寫記憶體時發生 race condition。

1. `ll $rt offset($rs)`：Load Linked，`lw` 之後硬體會開始標控並追蹤這個記憶體位址。
2. `sc $rt offset($rs)`：Store Conditional，跟 `sw` 一樣，但會先確認 `ll` 到 `sc` 之間該記憶體沒有被修改才會 `sw`。
    - 如果寫入 `$rt` 失敗，`$rt` 被清掉並設為 0。
    - 如果寫入 `$rt` 成功，`$rt` 被清掉並設為 1。

MIPS 規範：`ll` 與 `sc` 指令之間越短越好，且只能包含單純的暫存器運算指令，絕對不能插入其他的記憶體存取指令
