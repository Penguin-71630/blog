[IMPORTANT SIDE NOTES]

1. DMA path:
   Device Controller  --->  RAM (DMA buffer)  ---> interrupt ---> CPU ---> driver

2. Interrupt path:
   Device ---> interrupt controller ---> CPU ---> kernel ISR ---> driver

3. Storage read path:
   app -> syscall -> VFS -> FS layer -> block layer -> NVMe/SATA driver
       -> controller -> SSD
       -> DMA to RAM
       -> interrupt
       -> kernel wakes process
       -> app reads data

4. Memory hierarchy:
   Registers -> L1 -> L2 -> L3 -> DRAM -> SSD/HDD

MEMORY HIERARCHY SPEED / SIZE SUMMARY
──────────────────────────────────────────────────────────────────────────────────
  Registers    │ ~1-4 KB    │ 200-300 ps  │ inside CPU core
  L1 Cache     │   64 KB    │      1 ns   │ per-core, on-chip
  L2 Cache     │  256 KB    │   3-10 ns   │ per-core or shared, on-chip
  L3 Cache     │ 4-64 MB    │  10-20 ns   │ shared across cores, on-chip
  RAM          │ 4-256 GB   │  50-100 ns  │ off-chip, via Memory Bus
  SSD          │ 1-16 TB    │  ~100 µs    │ via PCIe / SATA
  HDD          │ 16-64 TB   │   5-10 ms   │ via SAS / SATA

KEY DATA PATHS
──────────────────────────────────────────────────────────────────────────────────
  READ  (program):  Device → Controller → PCIe Bus → I/O Buffer (DMA) →
                    RAM → L3 → L2 → L1 → Registers → CPU

  INTERRUPT:        Device asserts IRQ → Interrupt Controller (IRQ→INT mapping)
                    → Local APIC → CPU interrupted → CPU reads IVT[INT] →
                    jumps to ISR code

  FILE READ (OS):   Process syscall → VFS → Page Cache (hit?) →
                    Mapping Layer → Block I/O Layer → Block Device Driver →
                    Controller → Device → data returns up the same stack
